# laravel-znuny v0.2.0 — Generic Znuny support

- **Date:** 2026-10-09
- **Status:** Design approved in conversation; this document is the written spec.
- **Target release:** `v0.2.0` (breaking changes are allowed in `0.x` minors per SemVer)

## 1. Goal

v0.1.x only works against a web service whose REST routes are named after the
operations (`POST /<Operation>[/<ID>]`) and which exposes several non-core
operations. It also ships company-specific queue logic. v0.2.0 makes the
package work **out of the box against any Znuny installation** — in particular
the stock `GenericTicketConnectorREST` web service — while remaining fully
usable with custom web services through configuration.

Success criteria:

1. A fresh Znuny 7 with the stock `GenericTicketConnectorREST` web service works
   with only `base_url`, `username`, `password` configured.
2. Existing v0.1 deployments keep working by setting `'routes' => 'operation-name'`.
3. Any operation (core, add-on such as FAQ/ITSM, or custom) can be called
   through one generic API with routing, auth, error mapping, events and
   logging applied.
4. No company-specific behaviour or documentation remains in the package.
5. CI proves the declared support matrix (PHP 8.3–8.5 × Laravel 12/13).

## 2. Non-goals

- Importing Znuny web service YAML exports (possible later as a command).
- Pluggable "profile" classes with per-operation response normalisation.
- Two-factor tokens (`TwoFactorToken`) and `ImpersonateAsUser` as first-class
  config (they can still be sent through the generic payload).
- Returning ticket changes to Znuny from webhook listeners (the invoker's
  `HandleResponse` feature).
- Migrating consuming applications (done separately after the release).

## 3. Znuny facts this design relies on

Verified against the Znuny source (`dev` branch, tags up to `rel-7_3_7`):

- **Core operations** are only: `Session::SessionCreate/SessionGet/SessionRemove`,
  `Ticket::TicketCreate/TicketGet/TicketSearch/TicketUpdate/TicketHistoryGet`,
  `Ticket::TimeAccountingGet`, `User::OutOfOffice`. `QueueList`, `QueueGet`,
  `StateList`, `PriorityList`, `TypeList`, `CustomerUserGet` are **not** core.
- **Stock REST routes** — corrected 2026-10-11 after the integration run against
  Znuny 7.3.7: Znuny ships *two* GenericTicketConnectorREST examples.
  - `var/webservices/examples/GenericTicketConnectorREST.yml` (offered for import in
    the admin UI; Znuny 6.5.x and 7.x): `SessionCreate POST /Session`,
    `SessionGet GET /Session/:SessionID`, `SessionDelete DELETE /Session/:SessionID`,
    `TicketCreate POST /Ticket`, `TicketGet GET /Ticket/:TicketID`,
    `TicketSearch POST /Ticket/Search`, `TicketUpdate PATCH /Ticket/:TicketID`,
    `TicketHistoryGet GET /Ticket/History/:TicketID`.
  - `development/webservices/GenericTicketConnectorREST.yml` (older; many OTRS and
    Znuny installations were set up from it): as above, but
    `TicketSearch GET /Ticket`, `TicketHistoryGet GET /TicketHistory/:TicketID`,
    `TicketGetList GET /TicketList` and no `SessionDelete`.
- **Request parsing** (`Transport/HTTP/REST.pm`): route placeholders `:Name` are
  extracted and URI-unescaped; query parameters are split on `&`/`;`, `+` is
  treated as `%20`, values are URI-unescaped, **repeated keys become arrays**,
  bracket notation (`key[0]`) is not understood, nested structures cannot be
  expressed. For `GET` the body is ignored. Route data overrides query data.
- **Auth** can be sent as `SessionID`, or `UserLogin`/`CustomerUserLogin` +
  `Password` in the request data of every operation. Since **Znuny 6.5** it can
  also be sent as headers `X-OTRS-Header-SessionID`, `X-OTRS-Header-UserLogin`,
  `X-OTRS-Header-CustomerUserLogin`, `X-OTRS-Header-Password`.
- **Batching:** `TicketGet` and `TicketHistoryGet` accept comma-separated IDs.
- **Error formats:**
  - operation errors: HTTP 200 with `{"Error": {"ErrorCode": "<Op>.<Code>", "ErrorMessage": "..."}}`;
  - operation failures (`Success => 0`): HTTP 500, `text/plain` body
    `{"faultcode":"Server","faultstring":"..."}`;
  - no matching route: HTTP 500, plain text
    `HTTP::REST Error while determine Operation for request URI '<path>'.`
- **Error codes used by core operations:** `*.AuthFail`, `*.AccessDenied`,
  `*.MissingParameter`, `*.InvalidParameter`, `*.WrongStructure`,
  `*.EmptyRequest`, `TicketGet.NotValidTicketID`, `*.NotTicketData`,
  `Webservice.InvalidConfiguration`. Invalid-value messages look like
  `TicketUpdate: Ticket->QueueID or Ticket->Queue parameter is invalid!`.
- `TicketGet` checks permissions **before** existence, so a non-existent ticket
  usually yields `TicketGet.AccessDenied`.
- **Outbound events** (Znuny ≥ 6.5): invoker `Ticket::Generic` sends
  `{"Ticket": {TicketDeepGet data}, "Event": {"Event": "<Name>", "TicketID": ..., ...}}`.
  `TicketDeepGet` returns articles as `Articles` (list), the requested article
  as `Article` (hash), dynamic fields as flat `DynamicField_<Name>` keys and
  `CustomerUser` as a hash. The REST requester supports BasicAuth, JWT and
  arbitrary `AdditionalHeaders`. Response data returned to the invoker is
  interpreted as ticket changes.

## 4. Configuration

```php
return [
    'default' => env('ZNUNY_CONNECTION', 'default'),

    'connections' => [
        'default' => [
            'base_url' => env('ZNUNY_BASE_URL'),   // .../nph-genericinterface.pl/Webservice/<Name>
            'username' => env('ZNUNY_USERNAME'),
            'password' => env('ZNUNY_PASSWORD'),

            'routes' => env('ZNUNY_ROUTES', 'generic-ticket-connector'),

            'auth' => env('ZNUNY_AUTH', 'session'),                   // session | credentials
            'user_type' => env('ZNUNY_USER_TYPE', 'agent'),           // agent | customer
            'auth_transport' => env('ZNUNY_AUTH_TRANSPORT', 'auto'),  // auto | payload | headers

            'verify_ssl' => env('ZNUNY_VERIFY_SSL', true),
            'timeout' => env('ZNUNY_TIMEOUT', 30),
            'connect_timeout' => env('ZNUNY_CONNECT_TIMEOUT', 3),
        ],
    ],

    'session' => [ /* unchanged: cache_store, cache_prefix, ttl, auto_retry_on_expired */ ],

    'cache' => [
        'enabled' => env('ZNUNY_CACHE_ENABLED', true),
        'store' => env('ZNUNY_CACHE_STORE'),
        'prefix' => 'znuny:lookup:',
        'ttl' => ['queues' => 3600, 'priorities' => 3600, 'states' => 3600, 'types' => 3600, 'customers' => 600],
    ],

    'logging' => [ /* unchanged keys; log_responses is now implemented */ ],

    'dynamic_fields' => [],

    'http' => [
        'retries' => 3,
        'retry_delay' => 100,
        'batch_size' => 50,
    ],

    'webhooks' => [
        'enabled' => env('ZNUNY_WEBHOOKS_ENABLED', false),
        'route_prefix' => 'znuny/webhooks',
        'middleware' => ['api'],
        'auth' => [
            'type' => env('ZNUNY_WEBHOOK_AUTH', 'token'),   // token | basic | none
            'token' => env('ZNUNY_WEBHOOK_TOKEN'),
            'header' => 'X-Znuny-Token',
            'username' => env('ZNUNY_WEBHOOK_USERNAME'),
            'password' => env('ZNUNY_WEBHOOK_PASSWORD'),
        ],
    ],
];
```

Rules:

- Missing connection keys fall back to code defaults (`routes` →
  `generic-ticket-connector`, `auth` → `session`, `user_type` → `agent`,
  `auth_transport` → `auto`). Old published config files therefore get the new
  stock-Znuny behaviour; this is the main breaking change (see §14).
- Per-connection `retries`, `retry_delay`, `batch_size` override `http.*`.
- Removed keys: `queues` (whole block), `http.pool_size`, `cache.ttl.services`.
- All connection config is parsed and validated in one place
  (`ConnectionConfig`); invalid values throw `ZnunyConfigurationException`
  with a message naming the connection and key.

## 5. Routing and request building

### 5.1 Route definitions

- Format: `"METHOD /Path/:Param"` — the same notation as the Znuny admin UI.
  The method is optional (defaults to `POST`); allowed methods: `GET`, `POST`,
  `PUT`, `PATCH`, `DELETE`. A missing leading `/` is added.
- `routes` accepts:
  - a preset name (string);
  - an array of `Operation => definition`, optionally with
    `'extends' => '<preset>'` to start from a preset and override entries.
- Operations without a mapping fall back to `POST /<Operation>`.
- Unknown preset or unparsable definition → `ZnunyConfigurationException`.

### 5.2 Presets

| Preset | Operation → route |
|---|---|
| `generic-ticket-connector` (default) | the `var/webservices/examples` routes listed in §3 |
| `generic-ticket-connector-classic` | the `development/webservices` routes listed in §3 |
| `operation-name` (= v0.1 behaviour) | `TicketGet POST /TicketGet/:TicketID`, `TicketUpdate POST /TicketUpdate/:TicketID`, `QueueGet POST /QueueGet/:QueueID`; everything else via fallback `POST /<Operation>` |

### 5.3 Building a request

1. Resolve the route for the operation.
2. Fill each placeholder `:Name` from `payload[Name]`:
   - list values are joined with `,` (each element raw-URL-encoded, commas kept
     literal) — this enables batch `GET /Ticket/1,2,3`;
   - booleans become `1`/`0`; other scalars are cast to string and
     raw-URL-encoded;
   - missing/`null`/empty value → `ZnunyConfigurationException`
     ("Route `GET /Ticket/:TicketID` for operation `TicketGet` requires parameter `TicketID`").
3. `GET`: the remaining payload (placeholder keys removed) becomes the query
   string in Znuny's format:
   - scalars → `rawurlencode(key)=rawurlencode(value)`; booleans → `1`/`0`;
     `null` and empty lists are skipped;
   - lists of scalars → repeated keys (`States=open&States=new`);
   - associative arrays or lists containing arrays →
     `ZnunyConfigurationException` explaining that nested parameters require a
     body route (e.g. `routes['TicketSearch'] = 'POST /TicketSearch'`).
4. Every other method: JSON body containing the full payload (placeholder keys
   kept, as in v0.1). An empty payload is sent as `{}`, never `[]`.
5. Auth data is added according to §6 before steps 3/4.

### 5.4 Batching

`TicketGet` is called with up to `batch_size` IDs per request (default 50).
Results are returned in the order of the requested IDs; IDs Znuny does not
return are skipped. Input IDs are de-duplicated preserving order.

## 6. Authentication

- `user_type`: `agent` → login key `UserLogin`; `customer` → `CustomerUserLogin`.
- `auth = session` (default):
  - `SessionCreate` with `{<login key>, Password}`; the `SessionID` is cached
    per connection (existing `SessionManager`/`SessionStore`);
  - every call carries `SessionID`;
  - on `ZnunySessionExpiredException` (and `session.auto_retry_on_expired`):
    invalidate, create a new session, dispatch `ZnunySessionRefreshed`, retry
    the call once.
- `auth = credentials`: every call carries `{<login key>, Password}`; no session
  cache, no retry.
- `auth_transport`:
  - `auto` (default): headers for `GET` routes, payload for all others;
  - `payload`: always in the request data (query string for `GET`);
  - `headers`: always as `X-OTRS-Header-*` headers (Znuny ≥ 6.5).
  The rule applies to `SessionCreate` too (its stock route is `POST`, so `auto`
  sends credentials in the body).
- `*.AuthFail` mapping is mode-aware: in session mode (and not for
  `SessionCreate`) it means the session expired; in credentials mode and for
  `SessionCreate` it is `ZnunyAuthenticationException`.
- Missing `base_url`, `username` or `password` → `ZnunyConfigurationException`
  before any request is sent.

### 6.1 Runtime connections

- `Znuny::build(array $config)` accepts the same keys as a configured
  connection plus optional `name`. Unset keys use the defaults of §4.
- Connection name (also the session cache key):
  `name` if given, otherwise `ephemeral_` + `md5(base_url|user_type|username|auth)`.
- `usingCredentials(string $baseUrl, string $username, string $password, bool $verifySSL = true, int $timeout = 30, array $options = [])`
  stays and delegates to `build()`; `$options` is merged into the config
  (e.g. `['routes' => 'operation-name']`).

## 7. Public API

### 7.1 Manager / facade

`connection(?string)`, `build(array)`, `usingCredentials(...)`,
`connectionName()`, `client()`, **`call(string $operation, array $payload = []): array`**,
`tickets()`, `queues()`, `states()`, `priorities()`, `types()`, `customers()`,
`ping()`, `flush(?string)`, `flushAll()`. Facade `@method` docs are updated.

### 7.2 Client

- `call(string $operation, array $payload = []): array` — the single entry
  point for all requests (routing, auth, retries, errors, events, logging).
- `request()` remains as a deprecated alias of `call()`. Operation strings with
  path suffixes (`'TicketGet/123'`) are no longer supported.
- `ping(): bool` — session mode: fresh `SessionCreate`; credentials mode:
  `TicketSearch` with `Limit => 1`.
- `connection(): string`, `routes(): RouteMap`, `settings(): ConnectionConfig`.

### 7.3 Tickets

- `find(string $id, bool $withArticles = false, bool $withDynamicFields = false, bool $withAttachments = false): Ticket`
  (`withAttachments` implies articles: sends `AllArticles=1`, `Attachments=1`).
  No ticket in the response → `TicketNotFoundException`.
- `findMany(array $ids, bool $withArticles = false, bool $withDynamicFields = false, bool $withAttachments = false): Collection<int, Ticket>` (§5.4).
- `create(array $ticket)->withArticle(array)->withDynamicFields(array)->withAttachments(array<Attachment>)->save(): Ticket`
  — validates dynamic fields, sends `Ticket`, `Article`, `DynamicField`,
  `Attachment`; a missing `TicketID` in the response is a
  `ZnunyServerException`; the result is re-fetched with articles and dynamic
  fields (as in v0.1).
- `update(string $id, array $ticket = [], array $dynamicFields = []): void` —
  validates dynamic fields; both empty → `InvalidArgumentException`.
- `addArticle(string $id, array $article, array $attachments = []): ?string` —
  returns the `ArticleID` from the response.
- `close(string $id, string $state = 'closed successful'): void`.
- `history(string $id): Collection<int, HistoryEntry>` (`TicketHistoryGet`).
- `query()` and the shortcuts `where()`, `whereState()`, `whereQueue()`,
  `whereCustomerId()` remain.

### 7.4 Search builder

Unchanged API plus:

- date filters accept `DateTimeInterface` (`whereCreatedAfter/Before`);
- `whereChangedAfter/Before(DateTimeInterface)` → `TicketChangeTimeNewerDate/OlderDate`;
- `whereDynamicField(string $name, mixed $value, string $operator = 'Equals')`
  → `DynamicField_<name> => [<operator> => <value>]` (nested; needs a body
  route for `TicketSearch`, see §5.3);
- `withAttachments(bool $value = true)`;
- `orderBy()` accepts `asc`/`desc` as well as `Up`/`Down`;
- `get()`, `paginate()`, `lazy()` fetch through `findMany()`.
  Defaults stay as in v0.1 (`withArticles` and `withDynamicFields` are `true`
  for the builder).

### 7.5 DTOs

- Every DTO gets `public array $attributes` (complete raw Znuny data, default
  `[]`, last constructor parameter) and `attribute(string $key, mixed $default = null)`
  (dot notation). New constructor parameters are appended with defaults.
- `Ticket` adds (nullable strings): `stateId`, `stateType`, `priorityId`,
  `typeId`, `lock`, `owner`, `ownerId`, `responsible`, `responsibleId`,
  `service`, `serviceId`, `sla`, `slaId`. Parsing is tolerant:
  - articles from `Article` (list), else `Articles` (list), else a single
    `Article` hash;
  - dynamic fields from `DynamicField` (list), else flat `DynamicField_<Name>` keys;
  - `CustomerUser` given as a hash falls back to `CustomerUserID`.
- `Article` adds `to`, `cc`, `bcc` (`?string`), `isVisibleForCustomer`
  (`?bool`), `attachments` (`Collection<int, Attachment>`).
- New `Attachment`: `filename`, `contentType`, `content` (decoded bytes),
  `filesize`, `contentId`, `disposition`, `attributes`;
  `fromPath(string $path, ?string $filename = null, ?string $contentType = null)`,
  `fromContent(string $filename, string $content, string $contentType = 'application/octet-stream')`,
  `fromZnunyResponse(array)`, `toZnunyPayload()` (`Filename`, `ContentType`,
  base64 `Content`).
- New `HistoryEntry`: `historyType`, `name`, `createTime` (`?Carbon`),
  `createBy`, `articleId`, `attributes`.
- `Customer`, `Queue`, `State`, `Priority`, `Type`, `DynamicField`: unchanged
  plus `attributes`.

### 7.6 Input mapping

camelCase keys map to Znuny keys; unknown keys pass through unchanged.
Additions — ticket: `owner`, `ownerId`, `responsible`, `responsibleId`, `lock`,
`lockId`, `service`, `sla`, `slaId`, `pendingTime`, `customerUserId`;
article: `to`, `cc`, `bcc`, `replyTo`, `isVisibleForCustomer`, `historyType`,
`historyComment`, `mimeType`, `charset`, `noAgentNotify`,
`communicationChannelId`, `senderTypeId`. Boolean values become `1`/`0`.

### 7.7 Dynamic field validation

Types `string`, `integer`, `float` (int or float), `boolean`, `array` (list;
`allowed` applies to each element). Applied on `create()` and `update()`.
`znuny:generate-fields` maps `float` → `float`, `array` → `array`.

### 7.8 Lookup resources (custom operations)

`queues()->all()/find()/findByName()`, `states()->all()`,
`priorities()->all()`, `types()->all()`, `customers()->find()/tickets()` stay.
`QueueResource::resolve()` is removed. The README documents that these need
custom operations (`QueueList`, `QueueGet`, `StateList`, `PriorityList`,
`TypeList`, `CustomerUserGet`) and the expected response shapes. Missing
operations surface as `ZnunyRouteNotFoundException`.

## 8. Error handling

Order in the client:

1. Transport failure → `ZnunyConnectionException`.
2. JSON body containing `Error` (any status) → code-based mapping:

   | Code | Exception |
   |---|---|
   | `*.AuthFail` | session mode and not `SessionCreate`: `ZnunySessionExpiredException`; otherwise `ZnunyAuthenticationException` |
   | `*.AccessDenied` | `ZnunyAccessDeniedException` (new, extends `ZnunyException`) |
   | `TicketGet.NotValidTicketID`, `*.NotTicketData` | `TicketNotFoundException` |
   | `*.MissingParameter`, `*.InvalidParameter`, `*.WrongStructure`, `*.EmptyRequest` | `ZnunyValidationException`, or a subtype by message: `Ticket->Queue` → `InvalidQueueException`, `Ticket->State` → `InvalidStateException`, `Ticket->Priority` → `InvalidPriorityException`, `DynamicField` → `InvalidDynamicFieldException` |
   | `Webservice.InvalidConfiguration` | `ZnunyServerException` |
   | anything else | v0.1 heuristics (session expired, not found, invalid queue/state/priority/dynamic field, rate limit), then `GenericZnunyException` |

3. HTTP status ≥ 400 without `Error`:
   - 500 whose body contains `determine Operation`, or 404 →
     `ZnunyRouteNotFoundException` (new, extends `ZnunyConfigurationException`),
     message names method, path, operation, connection and points to
     `routes` / `php artisan znuny:routes`;
   - 401/403 → `ZnunyAuthenticationException`; 429 → `ZnunyRateLimitException`;
     other 5xx → `ZnunyServerException` (message from `faultstring` when the
     body is JSON, else the first 500 characters of the body); other 4xx →
     `GenericZnunyException`.
4. 2xx whose body is not a JSON object → `ZnunyServerException`.

All exceptions additionally expose `getHttpStatus(): ?int`. Text bodies are
stored as `['raw' => <first 1000 chars>]` in `getResponseBody()`.
`ZnunyConfigurationException` (new, extends `ZnunyException`) is thrown locally
for configuration problems (§4, §5, §6). Exceptions for HTTP 401/403 never
contain credentials (payloads are redacted, §9).

## 9. Events, logging, redaction

- One `Redactor` (deep, case-insensitive keys: `password`, `pw`, `userpw`,
  `newpw`, `sessionid`, `secret`, `token`, `accesstoken`, `apikey`,
  `authorization`, `otp`, `twofactortoken`, plus `X-OTRS-Header-Password`/
  `-SessionID`) replaces values with `[REDACTED]`; used for event payloads,
  logs and exceptions.
- Existing events keep their properties; additions are appended with defaults:
  `ZnunyRequestSent` + `method`, `path`; `ZnunyResponseReceived` + `status`;
  `ZnunyTicketUpdated` + `dynamicFields`; `ZnunyArticleAdded` + `articleId`.
- `ZnunySessionRefreshed` is now dispatched (§6). It carries only
  `connection` — it was never dispatched in v0.1, and session IDs must not be
  exposed to listeners.
- New `ZnunyWebhookReceived` (§10).
- Logs: request (`info`): connection, operation, method, path, redacted
  payload. Response (`debug`, only when `logging.log_responses`): connection,
  operation, status, duration in ms, redacted response with base64 `Content`
  values truncated. Error (`error`): connection, operation, method, path,
  HTTP status, error code, message.

## 10. Webhooks (Znuny → Laravel)

- Route `POST {route_prefix}/{event?}`, name `znuny.webhook`, registered only
  when `webhooks.enabled`; middleware = configured middleware + `znuny.webhook`.
- Middleware `AuthenticateWebhook` (alias `znuny.webhook`, usable in app routes):
  - `token`: accepts `Authorization: Bearer <token>` or `<header>: <token>`;
  - `basic`: HTTP Basic credentials (Znuny's built-in BasicAuth);
  - `none`: no check (only when configured explicitly);
  - comparison with `hash_equals`; an unconfigured secret or an unknown `type`
    rejects every request with 401 (fail closed) and logs a warning.
- Controller: body must be a JSON object, else 400. Parsing (`WebhookPayload`):
  - event: route parameter `event`, else `Event.Event`, else `Event` if string,
    else `unknown`;
  - ticket id: `Event.TicketID`, else `Ticket.TicketID`;
  - article id: `Event.ArticleID`.
- Dispatches `ZnunyWebhookReceived(string $event, ?string $ticketId, ?string $articleId, array $payload, array $parameters)`
  with helpers `ticket(): ?Ticket` (from the embedded `Ticket` data) and
  `is(string ...$events): bool`. Only scalars/arrays → safe for queued listeners.
- Response: HTTP 200 with `{}` (never data that the invoker would apply to the ticket).
- `WebhookEventMapper` and the 501 stub are removed.

## 14. Breaking changes

1. Default routes are now `generic-ticket-connector`; v0.1 behaviour requires
   `'routes' => 'operation-name'` (also for `build()`/`usingCredentials()`).
2. `QueueResource::resolve()` and the `queues` config block are removed.
3. `http.pool_size` and `cache.ttl.services` are removed.
4. `ZnunyClient::request()` no longer accepts path suffixes; it is a deprecated
   alias of `call()`. The `ZnunyClient` constructor parses its config array
   through `ConnectionConfig`.
5. Some failures map to different exceptions: `*.AccessDenied` →
   `ZnunyAccessDeniedException`; 4xx/5xx without `Error` body and non-JSON 2xx
   now throw instead of returning `[]`; `TicketCreate` without `TicketID` →
   `ZnunyServerException`.
6. `ZnunySessionRefreshed` carries only `connection`.
7. Event payloads contain `[REDACTED]` values instead of removed keys.
8. The webhook stub (501) and `WebhookEventMapper` are removed; webhook config
   gains `auth`.
