# laravel-znuny 0.3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the daily friction of 0.2.x (search, ticket actions, testing, Znuny setup) and fix the remaining API warts in one breaking release.

**Architecture:** Additions sit on the existing layers: filters on `TicketBuilder`, actions on `TicketResource`, a fake `ZnunyManager`/`ZnunyClient` pair under `src/Testing`, and a web service generator built from `RouteMap`. Breaking changes are limited to the four listed in the spec and fail loudly.

**Tech Stack:** PHP 8.3+, Laravel 12/13 components, PHPUnit 12, Orchestra Testbench 10/11, PHPStan 2 (level 8), Pint; Znuny 6.5.26/7.0.19/7.1.7/7.2.3/7.3.8 in Docker for the integration suite.

**Spec:** `docs/superpowers/specs/2026-11-06-v0.3-design.md`

## Global Constraints

- PHP `^8.3`, Laravel `^12.0 || ^13.0`; no new runtime dependency in `require`. Dev-only additions are allowed (Task 6 adds `symfony/yaml` to `require-dev`).
- PHPStan level 8 on `src` without baseline and without ignore comments (`composer analyse`); Pint (`vendor/bin/pint --test`).
- No silent behaviour change: every breaking change fails loudly or is listed in `UPGRADE.md` with old and new behaviour.
- No new option in a nested config block without the one-level merge in `ZnunyServiceProvider::mergeNestedConfig()`.
- No feature that only works on some of the five supported Znuny lines without saying so in the README.
- Repository artifacts (code, comments, commits, PR texts, docs) are English. Commits use the repo-local identity `Vitalis Feist-Wurm <hello@itsjustvita.com>`; check `git config user.email` before the first commit. No employer or internal application names anywhere.
- Integration tests need a running Znuny: `tests/Integration/docker/setup.sh` (default image 7.3.8), variables as printed by the script; run them at the end of each task that adds some.

## Review Focus

1. `Znuny::fake()` in an application whose Znuny connection is not configured at all (no `base_url` in the test environment) must still work. Test in Task 5.
2. Code that receives `ZnunyManager` through dependency injection instead of the facade must get the fake. Test in Task 5.
3. A typo in a method called on `Znuny::tickets()` must raise a `BadMethodCallException` that names `TicketResource` and the method, not an error from inside the builder. Test in Task 2.
4. `assign()` and `move()` with a numeric string: an `int` means an ID, a `string` is always a login or queue name. Test pins both in Task 3.
5. Generated YAML with values that YAML would misread (`:`, `#`, a leading `-`, `yes`/`no`/`on`, numbers, empty strings) must parse back to the same strings. Test in Task 6.

### Task 5: `Znuny::fake()`

**Files:**
- Create: `src/Testing/FakeZnunyManager.php`, `src/Testing/FakeZnunyClient.php`, `src/Testing/FakeZnunyState.php`, `src/Testing/FakeResponseSequence.php`, `src/Testing/StrayZnunyCallException.php`

**Interfaces:**
- Produces (facade, static):
  - `Znuny::fake(array $responses = []): FakeZnunyManager` — `$responses` keyed by operation name; `'*'` answers every operation without its own entry. Swaps the facade root and binds the fake as `ZnunyManager::class` in the container.
  - `Znuny::fakeTickets(array ...$tickets): array` — `['Ticket' => [...]]`; each ticket is merged over defaults that give a complete `Ticket` DTO; `TicketID` defaults to `'1'`, `'2'`, … by position.
  - `Znuny::sequence(mixed ...$responses): FakeResponseSequence` — consumed one per call; an exhausted sequence throws `StrayZnunyCallException`.
- Produces (`FakeZnunyManager extends ZnunyManager`, forwarded by the facade): `assertCalled(string $operation, ?Closure $callback = null): void`, `assertCalledTimes(string $operation, int $times): void`, `assertNotCalled(string $operation, ?Closure $callback = null): void`, `assertNothingCalled(): void`, `recorded(?string $operation = null): array` (list of `['connection' => string, 'operation' => string, 'payload' => array]`). Callbacks receive `(array $payload, string $connection)`. Assertions use `PHPUnit\Framework\Assert`.
- Behaviour:
  - A response is an array, a `Closure(array $payload, string $connection): array`, a `Throwable` (thrown; a `ZnunyException` gets operation and connection set when empty), or a `FakeResponseSequence` of those.
  - An operation without a response throws `StrayZnunyCallException` (extends `RuntimeException`, not `ZnunyException`) with "Znuny::fake() has no response for operation [{op}] (connection [{name}]).".
  - Calls are recorded before the response is resolved, across all connections (`connection()`, `build()` clones share one `FakeZnunyState`).
  - `FakeZnunyClient extends ZnunyClient` overrides `call()`, `ping()` (returns `true`, records nothing) and `sessionId()` (returns `'fake-session'`); it never sends HTTP. Its config is the connection's configured or runtime config with `null` values dropped, over the defaults `base_url` `https://znuny.fake/otrs/nph-genericinterface.pl/Webservice/fake`, `username`/`password` `fake`, so `timezone`, `search_limit` and `batch_size` from the application config still apply.
  - Lookup caching is off (`buildCacheManager()` returns a disabled `CacheManager`). Domain events are dispatched by the resources as usual; request events are not.
