# laravel-znuny 0.4.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every operation Znuny ships a typed API that is tested against real Znuny, make dates work in dynamic fields, and deprecate what does not rest on stock Znuny.

**Architecture:** Three new resources sit next to `tickets()` on `ZnunyManager` (`session()`, `timeAccounting()`, `users()`), each a thin class over `ZnunyClient::call()` with a DTO for what it returns. Znuny's formats (dates, CSV, key/value session data) are translated in small `final` support classes. Nothing existing is restructured.

**Tech Stack:** PHP 8.3+, Laravel 12/13 components, PHPUnit 12, Orchestra Testbench 10/11, PHPStan 2 (level 8), Pint; Znuny 6.5.26/7.0.19/7.1.7/7.2.3/7.3.8 in Docker for the integration suite.

**Spec:** `docs/superpowers/specs/2026-11-27-v0.4-design.md`

## Global Constraints

- PHP `^8.3`, Laravel `^12.0 || ^13.0`; no new dependency in `require`.
- PHPStan level 8 on `src` without baseline and without ignore comments (`composer analyse`); Pint (`vendor/bin/pint --test`).
- The rule of the spec: a first-class API exists for an operation if, and only if, Znuny ships that operation. No method, option or default that only one installation needs.
- Nobody has to change their web service, config file or permissions to keep using what works in 0.3.2. New config keys must work with config files published earlier (`http` and `session` are merged one level in `ZnunyServiceProvider::mergeNestedConfig()`).
- TLS verification and timeouts can only be changed through `verify_ssl`, `timeout` and `connect_timeout`.
- The only breaking changes are the four of the spec's section 7; each is listed in `UPGRADE.md`.
- A feature that needs a special web service or group says so in the README.
- New support classes are `final` and marked `@internal`.
- Tests are written first and watched failing. The test cache serializes and reads no objects back (`tests/TestCase.php`), so nothing the package caches may be an object.
- Repository artifacts (code, comments, commits, PR texts, docs) are English. Commits use the repo-local identity `Vitalis Feist-Wurm <hello@itsjustvita.com>`; check `git config user.email` before the first commit. No employer or internal application names anywhere.
- Integration tests need a running Znuny: `tests/Integration/docker/setup.sh` (default image 7.3.8), variables as printed by the script. Every task that adds integration tests runs them on 7.3.8 and on 6.5.26 (`ZNUNY_IMAGE=cygnusnetworks/znuny:6.5.26`); CI runs all six jobs. Switching versions needs a fresh instance: `docker compose -p laravel-znuny-integration down -v` first.
- Pushing to `main`, tagging and publishing a release are not part of this plan; they need the maintainer's explicit approval.

## Review Focus

1. A session that Znuny dropped is noticed during `session()->user()` on the default routes (`GET /Session/:SessionID`): the repeat must carry the new session ID in the path, not the old one. Test in Task 2.
2. `session()->logout()` when Znuny no longer knows the session: no exception, and the cached session ID is forgotten. Test in Task 2.
3. An out-of-office entry whose value contains a comma, a quote or a line break (`'search' => 'Miller, "Jo"'`): the CSV must parse back to the same entry, with no extra row or column. Test in Task 4.
4. A field declared `date` given a time close to midnight in another time zone (`2026-07-01 00:30` in `Asia/Tokyo` on a UTC Znuny): the day sent is `2026-07-01`, the day the caller named. Test in Task 6.
5. `options.headers` naming an authentication header (`X-OTRS-Header-Password`) or `options` that is not an array (a string from `.env`): the package's header wins in the first case, a `ZnunyConfigurationException` in the second. Tests in Task 7.
